# 写作风格指南

站点语言：简体中文，技术名词保留英文（skill、prompt、agent、star）。语气：编辑评论，
不是营销文案，也不是学术论文。范本：`web/src/content/insights/orange-line-illustration.md`。

## 开头

第一段直接给最有信息量的事实：这个 skill 是什么、从哪来、最硬的数据点（star 增速、
实战案例规模）。

**禁用开头**（这些是批量低质内容的指纹，一个都不能出现）：

- 「随着 AI 的快速发展…」及一切「随着…」句式
- 「在…的今天/时代/当下」
- 「近年来…」「众所周知…」
- 用 skill 的定义开头（「XX 是一个…的 skill」——读者从标题已经知道了）

**禁用结尾**：「未来可期」「让我们拭目以待」「值得关注」等展望式空话。结尾要么给
可迁移的结论，要么给行动建议，要么干脆停在最后一个实质观点上。

## 判断句优先

- 弱：「这个 skill 的失败案例部分比较有特色。」
- 强：「失败案例库才是这个仓库最值钱的部分——『什么不行、为什么不行』是花了真实
  生成成本换来的知识，而大多数人读原文时会跳过它。」

每个判断给证据：原文引句（短引，带引号）、数据、或结构性事实。没有证据的判断降级
为疑问或删掉。

## 增量自检

初稿完成后逐节问三个问题：

1. 这一节的内容在原 SKILL.md / README 里有没有被明说？有 → 这节是复述，压缩成一句
   或删掉。
2. 把领域名词遮住，这段话是不是对任何 skill 都成立？是 → 空话，重写到具体。
3. 一个已经读过原文的人，读这节会不会有「原来如此」的时刻？不会 → 增量不成立。

## 引用与署名

- 引原文短句用「」或引号，一次不超过两三句；不整段搬运。
- 提到作者用其自称的署名。
- 协议描述如实，商用限制必须出现在 limitations 里。
- 例子、数字、日期全部要能在源材料里找到出处，不确定的不写——文章走 PR 人审，
  但审的人默认事实层是对的，不要辜负这个默认。
