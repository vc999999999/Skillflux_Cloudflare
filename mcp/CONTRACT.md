# Current implementation contract

Authoritative models, canonical JSON and hashing primitives are in `src/shared.ts`. The catalog directory format and index schema are in `src/catalog/model.ts` with zod validation in `src/catalog/schemas.ts`. Node >=22.13.0 is required. The terminal user is anonymous and needs no account. There is no self-hosted server: skill content is distributed from a GitHub catalog repository.

## Catalog repository layout

```
skills/<id>/<version>/
├── skillflux.json          # declarative manifest (id, version, entry, deps, permissions, hosts, release)
├── skillflux.review.json   # review record + evaluation evidence bound to the content hash
└── SKILL.md and other text content files
index.json                  # generated by `skillflux catalog build`; the client's only entry point
```

`skillflux catalog build ROOT` scans every version directory, runs the automated checks, recomputes per-file sha256/size, verifies the review sidecar's `evaluation.contentHash` binding against the directory content, derives qualification, and writes `index.json`. `skillflux catalog build --check ROOT` fails when the committed index does not match the directory content — this is the CI consistency gate for the catalog repository.

Qualification derivation (identical semantics to the previous server gate): `approved` status + automated checks passed + `kind: "human"` evaluation bound to the current `contentHash` with passing purpose and boundary cases and installed+read evidence covering every declared host. `simulation` evidence never qualifies a version. Revocation changes the review status to `revoked`; dependents recursively lose their derived qualification.

## Trust and transport

There are no Ed25519 signatures. Trust anchors are: the GitHub account (2FA + branch protection, configured repository-side), HTTPS, commit-SHA pinning and per-file sha256. `init` resolves the default branch head to a 40-hex commit SHA via the GitHub API; every index and file download is then served from `raw.githubusercontent.com/<owner>/<repo>/<sha>/...` (or a mirror passed via `--source`). Redirects are rejected; response sizes and timeouts are bounded.

Local `search` runs entirely over the cached catalog index (24-hour TTL per project); capability queries never leave the machine. Plans are HMAC-sealed with a per-project secret, expire, and bind exact package digests, the project, the repository and host. Installation downloads each declared file and verifies size and sha256 against the index entry before anything is written.

## CLI

`skillflux catalog PATH [--check] [--output FILE]`, `init --project PATH [--repo OWNER/NAME] [--source URL] --host codex|claude|cursor|generic [--preauthorize-reviewed-text]`, `serve`, `search`, `plan`, `install`, `load`, `list`, `check-updates`/`outdated`, `pin`/`unpin`, `update [SKILL@VERSION] [--plan PLAN_ID] [--yes]`, `rollback`, `remove`, `privacy [status] [--reset-trust]`. Host MCP files are `.codex/config.toml`, `.cursor/mcp.json`, or `.mcp.json` for Claude/generic; the bootstrap skill is explicit-only in every host.

`install` executes only install/reinstall plans; changing an installed version requires an exact update plan reviewed by the user. MCP-channel installation additionally requires the local `--preauthorize-reviewed-text` consent; a model-provided boolean cannot supply it. `update` without an exact target is read-only. `check-updates` uses the 24-hour catalog index cache and reports unknown status honestly when offline; installation, upgrades and rollback require a reachable catalog. Rollback restores a previously verified lock state and re-checks revocations. Local edits and pins block destructive changes; edited files are preserved on removal.

Installed packages keep the same safety envelope as before: UTF-8 text only, at most 512 KiB / 64 files, per-file hashes, no shell/network/secret permissions, no reserved runtime filenames (`manifest.json`, `.skillflux-*.json`, `skillflux.json`, `skillflux.review.json` — the latter two are stripped from installed copies). Install anchors are local `.skillflux-manifest.json` records; every load re-verifies each file byte-for-byte and rejects symlinks, undeclared files and tampering. Installations remain transactional (staging → journal → atomic rename → lock history) with journal recovery on next open.

## MCP tools

`skillflux.search`, `skillflux.plan`, `skillflux.install`, `skillflux.load`, `skillflux.list`, `skillflux.check_updates`, `skillflux.pin`, `skillflux.update`, `skillflux.rollback`, `skillflux.remove`, `skillflux.privacy` (read-only). Advertising no longer exists anywhere in the protocol: no ad fields, no ad events, no house ads. Revocation information comes from the catalog index status/qualification fields.

## Static website

Public pages use a validated snapshot synced from the GitHub catalog repository. `publication:sync` resolves the head commit, downloads `index.json` plus every approved+qualified skill's files at that SHA, verifies per-file hashes and writes a `skillflux-publication/v2` snapshot: `{ schema, repo, commitSha, fetchedAt, items }`. `publication:build` atomically switches a complete snapshot+dist release keyed by commitSha; failed builds preserve the previous release. Revoked or needs-testing entries are not synced as installable content. Any approval, retest or revocation requires sync + rebuild + redeploy to change public HTML.
