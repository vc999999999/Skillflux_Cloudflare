# SkillFlux 架构改造：GitHub 目录仓库 + 免签名 + 无广告

## 目标架构（改造后）

```
维护者本地: skillflux catalog build → 提交 skills/ + index.json 到 GitHub 独立仓库
用户项目:   skillflux init --project . --repo <owner>/skillflux-catalog [--source <镜像>]
            → CLI/MCP 拉 index.json（GitHub API 解析 main → commit SHA，所有下载钉 SHA）
            → 本地搜索（搜索词不再出本机）→ 逐文件下载 raw URL → sha256 校验
            → 事务安装（staging/journal/原子 rename/lock 全部保留）
网站:       构建时从目录仓库拉 index.json + 文件 → 生成 publication v2 快照 → Astro 静态构建
            → Cloudflare Workers（页面代码零改动，仅数据层换源）
删除:       mcp/src/registry/ 全部（HTTP server/SQLite/Ed25519/广告计费/咨询/举报/审计/备份）、
            广告客户端代码、VPS Registry 部署
```

## Part A — 内容仓库（新建独立仓库，建议名 `skillflux-catalog`）

### 目录结构
```
skillflux-catalog/
├─ index.json                      # 构建生成，客户端唯一入口
└─ skills/<id>/<version>/
   ├─ skillflux.json              # 声明性 manifest（自声明字段）
   ├─ skillflux.review.json       # 审核旁挂（review + evaluation 绑定）
   └─ SKILL.md 及其他内容文件
```

### 数据格式（最大化复用现有类型）
- `skillflux.json` = 现有 `Manifest`（shared.ts:25-31）去掉 `quality/files`：id/version/name/description/category/tags/hosts/publisher/license/entry/permissions/dependencies/release/createdAt。校验复用 `registry/schemas.ts` 的 zod schema（迁出）+ `validation.ts:42-100` 的 id/semver/entry/路径规则。
- `skillflux.review.json` = `{status: approved|revoked|needs-testing, reviewer, reviewedAt, notes, revocationReason?, evaluation: {contentHash, tester, testedAt, environment, kind:'human', summary, hosts[], purposePassed, boundaryPassed, hostChecks[]}}`。绑定锚点沿用 `contentHash`（shared.ts:99-102，天然排除 quality 避免循环）。
- `index.json` 条目 = `SkillSummary`（shared.ts:35-41）+ `versions[]`（`SkillVersionSummary`，checkUpdates 的最小需求含 release.minClientVersion/breaking）+ `files[{path,sha256,size}]` + `downloadPrefix`（`raw.githubusercontent.com/<owner>/<repo>/` + 构建时的 commit SHA 由客户端拼接）。`digest` 定义改为 `contentHash(manifest)`（文件哈希已递归覆盖全部内容）。qualification 派生规则同现有 `isQualified`（database.ts:503-514）：approved + 自动检查过 + evaluation 绑定 contentHash + hosts 覆盖。

### 维护流程（对应用户说的"每次更新处理一下"）
```
技能目录里改文件 → skillflux catalog build（本地，扫描+算哈希+重验 review 绑定+生成 index.json）
→ git diff 审查 → commit + push
```
CI（新仓库 GitHub Actions）：push 时跑 `skillflux catalog build --check`，index 与提交内容不一致即失败——这是免签名模型下的主要完整性防线。分支保护/2FA 在 GitHub 侧配置（计划中列为需用户手动操作的步骤）。

## Part B — mcp 包改造

### 新增 `mcp/src/catalog/` 模块
- `scan.ts`：从 `registry/scan.ts` 迁移（扩展名黑名单、secret 模式、路径保留名），作为 catalog build 的自动检查器
- `build.ts`：扫描 skills/*/*/ → 算逐文件 sha256/size → 校验 skillflux.json 与 review 绑定 → 派生 qualification → 输出 index.json；`--check` 模式对比已提交 index
- 保留名扩展：`skillflux.json`、`skillflux.review.json` 加入 `RESERVED_INSTALL_FILES`（validation.ts:8）

### 新增 `runtime/catalog-client.ts`（替代 api-client.ts）
- `resolveHead(repo)`：GitHub API `commits/main` 拿 commit SHA（缓存，失败时回退 raw+分支名并靠哈希校验兜底）
- `fetchIndex(repo, sha)`：拉 `<source>/<owner>/<repo>/<sha>/index.json`，本地缓存于 `.skillflux/cache/`，TTL 24h
- `fetchFile(url)`：逐文件下载，复用 `readLimitedBody`（api-client.ts:149-175）的限额逻辑
- 默认 source = `https://raw.githubusercontent.com`；`--source` 参数预留镜像覆盖

### runtime.ts 手术点
- `search`（:100-112）：改为缓存 index 本地过滤（query 关键词匹配 name/description/tags + category/host 筛选 + 排序），relevance 评分本地实现
- `createPlan`（:114-186）：依赖解析改查 index；`ResolutionPlanBody.registryOrigin`（model.ts:75）改为 `{repo, source, indexSha256, indexUrl}`
- `executePlan`（:204-330）：`client.getBundle`（:247）改为按 manifest.files 逐文件下载 + 现有 sha256/size 校验；`getQualification`（:249→:788-808）改为安装时校验 index 内 qualification 与 review 绑定并落盘 `.skillflux-manifest.json`（替代 envelope + qualification 两个文件）
- `getRevocations`（:810-830）：删除；撤销信息来自 index 的 status/qualification 字段
- `checkUpdates`（:383-432）：数据源改 index（含全部版本），缓存 key 从 `client.origin` 改为 repo 标识
- 广告全删：`selectAdvertisement`/`recordImpression`/`hideAd`/`reportAd`/`flushEventOutbox`/`emitAdEvent`/`readFrequency`（:583-733, :865-870, :977-993）、model.ts:222-260 广告类型、`ad-frequency.json`/`event-outbox.json` 路径、policy 的 adsEnabled

## 风险与边界（如实声明）

- **信任模型**：免签名后信任根 = GitHub 账号（2FA + 分支保护）+ HTTPS + 逐文件 sha256 + plan 绑定 indexSha256 + CI 一致性检查。账号失窃即内容失窃；索引回滚攻击无签名防线（plan 密封 + 版本固定缓解）
- **国内可达性**：暂不处理，`--source` 预留；真实验收阶段如果 raw 拉取在本地环境不可达会如实报告
- 需要用户手动操作：创建 GitHub 仓库、push、配置分支保护与 Actions；最终 `wrangler deploy` 需登录态
- `web/data/registry-publication.json` 旧 dev 快照（9 技能）会被新格式替换；当前工作区未提交的 20 个文件（验收修复）建议先单独提交，再开始本次改造，避免 diff 混淆
