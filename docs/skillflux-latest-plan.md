# SkillFlux 最新完整计划

更新日期：2026-09-14  
文档用途：统一产品定位、功能范围、技术架构、业务规则和完整验收标准。

本文保存我们最新确认的完整方案，不是 MVP 或演示版方案。实现时不能通过删除功能、跳过异常情况、填入伪造数据或仅展示界面来宣称完成。本文描述目标与约束，不等于正式域名、npm 包、精品内容和广告业务已经上线；实际完成证据另外记录在验收文档中。

## 1. 执行摘要（Executive Summary）

### 1.1 要解决的问题

Skill 来源分散，用户难以判断哪些适合自己的任务、哪些经过实际测试，以及安装后如何维护。用户不希望为了使用不同能力而预先下载大量 Skill，也不希望被自动升级或不明来源的内容影响当前项目。

SkillFlux 提供两层能力：公开静态网站负责整理和发现；npm + MCP 负责在用户明确调用后，从云端搜索经过质检、专人维护的精品 Skill，并按需加载到项目。

### 1.2 已确认的产品决策

| 事项 | 最新决定 |
| --- | --- |
| 网站定位 | 静态 Skill 来源黄页、场景选型内容与精品版本目录，供人和检索系统阅读 |
| 原有文章 | 整合到“场景与选型”；保留有价值的内容与旧 URL，不能把编辑分析写成人工实测 |
| 精品分发 | 一个 SkillFlux npm 入口 + 本地 MCP + 云端 Registry，显式调用、按需搜索与下载 |
| 内容维护 | 平台挑选并维护；自动检查与真实人工使用测试共同决定版本资格 |
| 普通用户账号 | 不需要注册、登录、会员或个人中心 |
| 更新提醒 | 纳入本地 npm/MCP 链路；只读检查与实际升级分离 |
| 收入来源 | 明示的一句话广告；广告主通过商务联系、线下合同与结算合作 |
| 运营权限 | 内部运营 token，不设计面向终端用户或广告主的账号系统 |
| 工程划分 | `web/` 与 `mcp/` 两个独立目录；运行数据不能混入网页或 npm 发布产物 |
| 交付要求 | 完整实现、真实接口、完整异常处理和实际验证；不是只完成首页或原型 |

### 1.3 核心使用场景

1. 用户在自己的项目安装 SkillFlux npm 包并初始化宿主配置。
2. 用户明确调用 SkillFlux，描述需要的能力。
3. AI 通过本地 MCP 搜索云端经过挑选、质检和维护的 Skill。
4. 用户或既有项目授权策略允许安装后，运行时按明确版本下载、验签、安装并更新项目锁。
5. 运行时把需要的 Skill 正文和资源返回当前会话，宿主 AI 用它完成用户任务。
6. 符合投放条件时，系统提供一句带“广告”标识的产品推荐，与 Skill 内容分开。
7. 后续调用可以检查已安装 Skill 的更新；发现新版不等于获得升级授权。

网站不是线上 AI 工作台，不负责直接读写访客电脑中的项目。

### 1.4 成功标准

- 核心公开内容在构建后的 HTML 中完整存在，禁用 JavaScript 仍能阅读和访问详情。
- npm 包能在干净项目安装，并通过真实 stdio MCP 完成搜索、计划、授权安装和同轮加载。
- 所有公开 Skill 正文、清单、资源和下载入口执行一致的版本资格与撤销检查。
- 不重复计费、不超额预留预算、不把预览或单纯返回广告数据算作曝光。
- 完整功能、类型检查、打包、静态发布、浏览器操作与备份恢复有可复现的验收证据。

搜索收录量、AI 引用量、广告点击和收入属于上线后的实际经营指标，不预填数字，也不保证收录、排名或模型采用。

## 2. 用户体验与功能（User Experience & Functionality）

### 2.1 角色与用户故事

| 角色 | 用户故事 | 验收条件 |
| --- | --- | --- |
| 网站访客 | 我想按来源、用途和标签查找 Skill 信息，以便决定下一步去哪里了解 | 来源目录、分类、标签、详情、搜索和筛选可用；明确收录不等于质检 |
| 项目使用者 | 我只想接入一个 SkillFlux，在需要时获取合适能力 | 入口显式触发，搜索云端精品，不预装整个库；下载与加载作用于指定项目 |
| 已安装用户 | 我想知道项目中的 Skill 是否有更新，但不希望自动改变项目 | 只读检查展示当前与目标版本、变更和风险；固定版本和升级授权有效 |
| 内部维护者 | 我想查看完整内容和测试记录后决定发布或撤销 | 文件、差异、评测、审核与历史可查；后端发布门禁不能被界面绕过 |
| 广告合作方 | 我想提交产品与联系方式，由平台安排合作 | 咨询真实保存并去重，可处理状态；提交不等于购买、签约或自动投放 |
| 广告运营者 | 我想管理活动、预算、举报和报表 | 活动增改启停、非计费预览、处理记录和 CSV 可用；账本与指标口径明确 |

### 2.2 公开网站信息架构

| 页面/入口 | 主要内容与行为 |
| --- | --- |
| `/`、`/en/` | 产品定位、来源搜索、来源分类、目录入口、场景选型、精品快照与接入说明 |
| `/directory/` | 完整来源黄页，关键词、来源分类、地域/语言维度和信任标签筛选 |
| `/category/:slug/` | 某一来源分类的静态聚合页 |
| `/tag/:tag/` | 某一标签的静态聚合页 |
| `/site/:slug/` | 外部来源介绍、原始链接、标签、维护时间、关联来源和收录边界 |
| `/registry/` | 精品 Skill 静态快照，关键词、能力分类、宿主、排序、分页与详情链接 |
| `/skills/:id/` | 当前最高合格版本；如果没有可用版本，展示公开状态，不冒充可安装内容 |
| `/skills/:id/versions/:version/` | 固定版本详情、变更、质检摘要、资源和安装命令；不可用版本保留状态说明 |
| `/scenarios/` | “场景与选型”内容入口 |
| `/scenarios/:slug/` | 来源比较、按需接入、版本维护等具体指导，关联目录和接入步骤 |
| `/guides/`、`/insights/` | 保留已有指南、分析文章及有价值的旧 URL |
| `/setup/` | npm 获取、项目初始化、宿主配置、显式调用、授权、更新与排错说明 |
| `/quality/` | 质检标准、人工评测与自动检查的区别、版本资格和撤销规则 |
| `/advertise/` | 广告业务说明、计量边界和真实商务咨询表单 |
| `/report/` | 广告举报，支持活动/决策信息和举报理由 |
| `/contact/`、`/privacy/`、`/terms/` | 平台联系、数据用途、权限边界和使用说明 |
| `/console/` | 内部运营入口，不进入公开搜索索引，不是终端用户登录系统 |
| 404 页面 | 明确不存在的地址，提供返回目录的路径，不跳转成其他 Skill 版本 |

公开核心页面提供中英文界面。原始 Skill 文本、维护者摘要和仅中文的已有文章保留原语言，不伪造翻译或评测；语言切换应说明实际内容语言并保留筛选条件。

### 2.3 黄页、精品与文章的关系

- 黄页是外部来源索引。收录、推荐标签和来源信任标签不证明其中每个 Skill 已经通过平台测试。
- 精品库是平台管理的具体版本集合，必须通过版本级质检，才提供可安装正文和资源。
- 文章是解释、比较和使用指导。文章引用某个 Skill，不等于批准该 Skill 进入精品库。
- 没有合格精品时，展示真实空状态，并允许继续浏览来源黄页；不能拿开发样例填充精品目录。
- 自然检索结果与广告分开，付费合作不替代质量审核，也不偷偷改变自然排名。

### 2.4 网站搜索与交互

- 来源黄页在静态数据上筛选；精品目录在已验签的静态发布快照上筛选。
- 搜索、分类、宿主、排序和分页状态使用 URL 参数，可复制、刷新恢复，并支持浏览器前进后退。
- 切换语言保留相关查询参数；清除筛选回到完整集合，不删除无关追踪参数。
- 提供正常、空结果、不可用、加载中、失败、重试、操作成功与复制失败反馈。
- 不依赖 JavaScript 才生成主要条目；JavaScript 只增强交互。
- 详情页复制固定版本命令，不自动下载或修改用户电脑。
- 支持键盘、可见焦点、跳转正文、移动端导航和窄屏换行；不能靠隐藏溢出裁掉必要内容。

### 2.5 精品版本详情

每个公开版本至少包含：

- 名称、标识、版本、用途、分类、标签、维护者和许可证。
- 支持的宿主、权限声明、精确依赖、入口文件和内容摘要值。
- 变更摘要、破坏性变更提示、最低客户端版本和维护时间；历史缺失字段如实标记。
- 自动检查结果、人工实测公开摘要、用途/边界测试与宿主检查信息。
- 该版本的完整文本资源，作为文字展示，不在页面中执行。
- 固定版本安装命令、版本历史、相关接入和更新维护入口。
- 静态快照时间及“安装和加载仍需检查云端当前状态”的说明。

撤销或待补测版本不展示可安装正文和下载入口，只展示允许公开的状态、原因及其他合格版本入口。

### 2.6 内部维护与运营台

运营台使用服务端配置的高熵 Bearer token。token 只保留在当前页面内存，连接后清空输入框，刷新、断开或鉴权失效后清除，不写入 URL、localStorage、sessionStorage 或公开构建。处置类操作必须记录操作员标识；单一共享 token 下“处理人”属于自报声明，需要可归因审计时应为每个操作员签发命名 token。

必需模块：

1. 完整 Skill 包录入、自动检查结果、待审列表及版本历史。
2. 待审包完整文件阅读、原始内容导出及与相关版本的差异比较。
3. 人工测试材料录入、公开摘要选择、批准、驳回、补测与撤销。
4. 广告活动创建、编辑、启用、暂停、预算和时段管理，以及不计费预览。
5. 商务咨询查询、筛选、分页和处理状态。
6. 广告举报详情、驳回或暂停处置、处理人和理由。
7. 按日期/活动查看指标，导出 CSV，展示指标定义。
8. 操作审计查询、筛选和完整分页，不能静默截断旧记录。

各模块独立处理加载与失败；一个接口失败不能导致整个运营台不可用。关键保存操作必须得到服务端真实确认，不能用前端假成功代替。

### 2.7 非目标与禁止替代

不建设普通用户注册登录、会员系统、广告主自助账号、在线支付或公开作者投稿；不建设线上 AI 执行工作台；不自动下载全部 Skill；不在未授权时更新项目；不保证第三方模型输出广告或搜索系统收录内容。

这些是已确认的边界，不是为了减少实现量临时删减的功能。

## 3. AI 与 Skill 系统要求（AI System Requirements）

### 3.1 npm 入口与显式调用

npm 包提供 CLI、项目级 Bootstrap Skill 和本地 stdio MCP。用户只需要接入一个 SkillFlux 入口，再通过它搜索和加载云端能力。

初始化必须限定在用户指定项目，保留无关宿主配置，不能覆盖用户其他 MCP 服务或写入不必要的全局配置。支持 Codex、Claude、Cursor 和通用宿主；各宿主需要显式启用并调用入口，不能假设新下载的文件会立刻被宿主自动发现。

MCP 工具职责：

| 工具 | 职责 |
| --- | --- |
| `skillflux.search` | 搜索云端合格版本，返回匹配理由和可供选择的信息 |
| `skillflux.plan` | 解析明确版本和依赖，生成绑定项目、权限、锁状态与有效期的计划 |
| `skillflux.install` | 在项目授权策略允许时安装计划；校验签名、资格、内容与撤销 |
| `skillflux.load` | 校验已安装内容，返回当前任务需要的入口与资源，不自动执行脚本 |
| `skillflux.list` | 查看项目已安装版本和状态 |
| `skillflux.check_updates` | 只读检查当前与可用版本、兼容信息、变更和缓存新鲜度 |
| `skillflux.pin` | 明确设置或解除版本固定策略 |
| `skillflux.update` | 只执行用户明确批准的精确升级计划，不隐式解析任意最新版 |
| `skillflux.rollback` | 在安全资格与本地保护检查通过后回滚 |
| `skillflux.remove` | 按项目范围移除指定内容，保护无关文件 |
| `skillflux.privacy` | 只读查看广告、隐私等本地策略状态 |

初次安装的项目级纯文本预授权必须由用户明确设置；AI 传入一个“用户已同意”的布尔值不构成权限依据。初次预授权不能替代升级时对具体目标版本和破坏性变更的确认。

广告开关、匿名标识重置等本地策略变更只能通过 `skillflux privacy` CLI 执行；MCP 工具保持只读，宿主 AI 不能自行重新开启用户已关闭的选项。项目策略文件受运行时校验与符号链接保护，但对拥有同等文件权限的宿主 AI 不构成强边界；授权模型的目标是防止 SkillFlux 自身静默变更，而不是防御有意的本地篡改。

### 3.2 质检与人工维护

发布前必须同时满足：

1. 自动安全检查通过：文件路径、格式、体积、哈希、入口、权限与依赖符合策略。
2. 许可与再分发核验通过：声明许可证允许平台再分发全文与签名包，或已取得来源方授权；不允许再分发的内容只能进入黄页索引，不能进入精品库。
3. 真实人工用途测试通过：记录输入、预期、实际结果、执行方法与证据。
4. 真实人工边界测试通过：覆盖不适用情况、失败情况与能力限制。
5. 每个声明宿主都有安装和读取验证；不能声称没有测试过的宿主支持。
6. 测试记录绑定当前提交内容的 `contentHash`。
7. 维护者完成独立批准操作，决定可公开的摘要。

自动扫描不代表效果测试。`simulation` 可以留档，但不能满足真实发布门槛。最新人工测试失败时，不能跳过它、选用更早的通过记录继续批准。

测试程序可以在隔离临时数据库中模拟维护者输入，以验证工作流；这类记录必须明确标识为合成测试材料，不能进入生产精品快照，也不能对外宣传为真实专人实测。

### 3.3 不可变版本与历史补测

- 已签名发布包不可覆盖；内容改变必须发布新版本。
- 依赖必须是明确版本且当前合格；不允许安装依赖不合格的上层包。
- 同一计划内同一依赖出现不同版本要求时解析失败并明确报错，不做隐式版本选择；不存在同一项目同时安装同一 Skill 两个版本的语义。
- 撤销应递归影响固定依赖它的版本，所有公共资源入口使用一致门禁。
- 历史 `approved` 包缺少当前要求的评测时，标记为 `needs-testing` 并停止提供可安装正文。
- 历史版本允许补充真实评测并再次批准，恢复同一版本资格；不得强迫通过修改原包或新发版本来回避补测需求。
- 补测通过独立签名 `QualificationProof` 绑定原 `id`、`version`、`digest`、`contentHash` 和公开评测摘要；原包字节、摘要、大小和创建时间不变。
- 私人测试输入、输出、环境和操作员笔记只在鉴权后台可见。
- 如果旧包本身已经包含不应公开的信息，不能同时“改字节脱敏”和“保持原摘要”；应撤销旧包，并以新版本发布脱敏内容。

### 3.4 更新提醒、升级和离线

更新检查与升级是两件事：

- `check-updates` / `outdated`（CLI 子命令，对应 MCP 工具 `skillflux.check_updates`）只读比较，不替换安装内容或项目锁中的精确版本。
- 返回当前版本、可用版本、变更摘要、破坏性变更、宿主与最低客户端兼容信息。
- 普通版本提醒允许使用最长 24 小时缓存，并显示缓存时间；主动检查可以刷新。
- 安全撤销和资格检查独立处理，不能被普通更新缓存覆盖。
- 固定版本仍能看到更新信息，但普通升级不能悄悄替换；升级前必须明确解除固定。
- 升级计划固定具体目标，执行前重新核验权限、锁状态、依赖、资格与撤销。
- 非交互 CLI 升级需要明确确认参数；MCP 升级只接受已批准计划 ID。
- 计划批准在 MCP 通道是约定级约束：协议无法证明用户真的审阅了计划，依赖宿主呈现计划内容并等待用户明确指令后再调用 `skillflux.update`。需要强执行时走 CLI 确认路径，不能把“AI 自行生成了计划又执行了它”视为有效授权。
- 本地编辑、文件或清单篡改、失效计划、不兼容版本和撤销状态应阻止执行；失败保留原有效状态。
- 回滚不能绕过同样的安全检查，也不能恢复已撤销或失去资格的内容。
- 离线只允许按策略读取此前已经安装、验签且有对应资格证明的内容，明确披露缓存与未知状态；不把未知说成“最新”或“安全状态已确认”。
- 离线时本地缓存的过期资格证明仍可加载，但必须向调用方披露证明生成时间与“当前云端资格未知”；恢复在线后必须重新核验。
- 已知的资格撤回必须保留，不能用旧缓存在离线状态恢复授权。
- 应用或 MCP 没有运行时，不提供虚构的实时推送承诺。

云端 Skill 内容更新与 npm 客户端更新分开管理；内容更新不必然要求重新安装 npm 包。

### 3.5 广告输出规则

广告是业务输出层，不是 Skill 指令的一部分：

- 正常情况下最多一句，带清晰“广告”标识和产品链接。
- 不修改原始 Skill 文件，不把推广内容写进搜索结果的自然排序或质检判断。
- 不上传完整用户任务、源码、密钥或最终回答来选择广告；只使用必要的能力分类和上下文声明。
- 默认上下文为 `unknown`，不投放；敏感、拒绝、失败、空结果、用户关闭广告等情况也跳过，不投自有替代广告。
- 明确普通场景没有付费匹配时，可以使用经过配置的 SkillFlux 自有广告；广告接口失败不能伪造本地兜底广告。
- 第三方宿主的普通 MCP 输出只提供独立结构化广告字段，由宿主决定是否呈现，不能保证 AI 最后一定复述。
- 受控 CLI 文本输出在主任务成功、有非空输出且广告可用时追加一行；广告故障不能让已成功的任务失败。
- JSON 模式保持正文数据与广告字段分离，不能把广告追加进原始 JSON 文本而破坏解析。
- 受控命令需要主动读取运行时提供的上下文，不能把任意命令包装一下就宣称它已使用 Skill。

### 3.6 广告预算与计量

- 商务流程是咨询、平台跟进、线下合同/付款、平台配置活动；不做广告主自助购买。
- 活动包含产品/广告主、文案、落地页、能力分类、投放时段、预算、CPC、UTC 每日付费决策上限和启停状态。
- 预览不分配正式决策、不生成收费 token、不预留预算，也不增加曝光和点击。
- 签发付费决策时原子预留一次 CPC，避免并发超过预算或日上限；不能只在请求进入时检查。
- token 最长有效 10 分钟，冻结签发时的文案、URL 和 CPC；自然结束活动不能改变尚未过期 token 的既有条款。
- 首次有效点击计费；重放与并发点击不能重复扣费；过期预留必须释放。
- 暂停活动永久作废未使用 token 并释放对应预留；重新启用不能复活暂停前的 token。
- 事件 ID 绑定原事件类型与内容，不能被复用成不同曝光、点击或举报。
- 广告 URL 限制安全公开 HTTPS 目标，拒绝本地、内网、IP 字面地址和不合规协议；这不等于永久保证外部落地页安全。

指标口径：

| 指标 | 定义与边界 |
| --- | --- |
| 决策 | 系统签发推荐的次数，不等于实际展示 |
| 曝光 | 客户端确认广告已输出的唯一事件，不证明真人一定看见 |
| 点击 | token 校验通过并去重后的点击事件 |
| 覆盖范围 | 曝光确认依赖客户端配合：普通第三方 MCP 客户端通常不会回报确认，曝光与 CTR 分母实际只覆盖受控 CLI 与主动确认的客户端，报表必须标注该边界 |
| 花费 | 有效首次点击进入账本的 CPC 金额，不冒充已经收款 |
| CTR | 选定时间内唯一付费曝光中后来被点击的占比，按曝光 UTC 日期归组；排除自有广告，无分母显示未知/空值 |
| 举报 | 实际提交并保存的举报，不因前端按钮点击即计入 |

点击与花费按实际点击日统计，因此不能直接用某日全部点击除以某日全部曝光计算上述 CTR。普通 MCP 返回广告数据、JSON 返回字段和网页预览均不能假装已经展示。

## 4. 技术规格（Technical Specifications）

### 4.1 总体架构

```text
公开访客、搜索系统、AI 检索
          │ 读取 HTML / JSON / 文本索引
          ▼
web/ 静态站与已验签发布快照
          ▲
          │ 同步 → 验签 → 构建 → 成功后发布
          │
云端 Registry（属于 mcp/ 服务端）
  ├─ 精品版本与资源、人工评测、资格证明、撤销
  ├─ 搜索与依赖元数据、签名发布快照
  └─ 广告活动、预算账本、咨询、举报、指标、审计
          ▲
          │ HTTPS：检索词、元数据、按需内容
          │
用户项目中的 npm Runtime + 本地 stdio MCP
  ├─ 显式 SkillFlux Bootstrap
  ├─ 授权计划、验签安装、精确版本锁和本地缓存
  ├─ 更新检查、固定版本、升级、回滚和移除
  └─ 向宿主返回需要的 Skill 文本与独立广告字段
          ▲
          │ 用户明确调用
          ▼
用户的 AI 宿主完成原任务
```

网页静态化与后端持久服务不矛盾：公开内容通过构建发布；咨询提交、举报、运营写入、预算事务和实时资格校验由后端完成。不能只靠静态 HTML 实现这些状态与账本。

### 4.2 工程与存储划分

```text
skillflux/
├─ web/                 Astro 静态网站、页面组件、内容数据、发布脚本
│  ├─ data/             来源目录和公开发布快照
│  ├─ src/              页面、索引与交互
│  ├─ scripts/          同步、原子构建与浏览器验收
│  └─ tests/            单元与发布集成测试
├─ mcp/                 npm 包、CLI、本地 Runtime、MCP 与云端 Registry
│  ├─ src/runtime/      本地计划、安装、锁、更新和权限策略
│  ├─ src/registry/     HTTP API、持久数据、评测、广告及运营
│  ├─ skills/           显式 Bootstrap Skill
│  ├─ catalog/          开发样本，只能待审，不能自动作为生产精品，也不进入 npm 发布包
│  └─ tests/            协议、安全、计费、恢复与运行时测试
├─ docs/                产品计划、运行说明和验收证据
└─ compose.yaml         网站和 Registry 的独立服务配置
```

云端运行数据采用独立持久目录/卷，保存 SQLite、签名私钥与后台业务记录。用户项目内的 `.skillflux/` 保存其本地配置、精确锁、缓存和必要证明。二者均不能进入静态站目录或 npm 发布包；公开网站只包含允许公开的数据。

技术基线：Astro 静态构建，TypeScript，Node.js CLI/HTTP 服务，MCP SDK，SQLite 持久存储，SHA-256 内容摘要与 Ed25519 签名。不为改版迁移到无必要的新前端框架。

### 4.3 Registry 与数据边界

核心实体包括 Skill 版本、包文件、自动检查、人工评测、审核历史、外置资格证明、依赖与撤销、广告活动、决策及预留、事件去重、计费账本、商务咨询、广告举报和审计记录。

公开 API 支持搜索、合格版本详情、版本状态、文本资源、签名包、公钥、资格证明、撤销和静态 publication。运营写接口集中在受 token 保护的管理路径。未配置有效运营凭据时，不开放管理写入。

管理列表必须服务端筛选和分页，公开内容不返回待审、驳回版本的私人正文或驳回笔记。报表 CSV 防止公式注入。

### 4.4 静态发布与 SEO / AI 可读性

- HTML、详情、分类、标签、场景文章和机器索引来自一致的数据源。
- 提供 canonical、hreflang、结构化数据、sitemap、robots、`/index.json`、`/skills-index.json`、`/scenarios/index.json`、`/llms.txt`、`/llms-full.txt` 和已有 RSS。
- URL 中的交互筛选参数不制造无限数量的索引页；详情使用稳定规范地址。
- 运营台 noindex，不进入 sitemap；robots 不是身份验证或安全边界。
- 同步器验证公钥、签名、分页完整性、同一 revision、版本资格、评测绑定和包内容摘要。
- 首次信任须提供可信公钥或明确接受 TOFU；后续公钥变化必须拒绝自动迁移。
- 密钥轮换只能带外完成：由运营者重新下发可信公钥，或通过携带新公钥声明的新 npm 客户端版本迁移，并保留轮换记录；不存在客户端自动跟随新密钥的通道。密钥泄露场景按撤销流程处理，不能用轮换通道静默替换。
- 批准、补测、更新和撤销后同步重建；不能指望静态站因 API 数据变化而自动改写已部署页面。
- 原子发布先在临时目录同步与构建，全部成功后一次切换当前版本；失败保留上一份有效站点和快照。
- 持续同步流程遇到失败记录错误并重试；相同 revision 可以跳过，网站代码变化时可强制重建。
- 紧急撤销还需要处理部署端/CDN 缓存；不能声称已追回用户下载或模型已经读入的旧文字。

主要工程命令：

```bash
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run pack:mcp
npm run smoke:package

# REGISTRY_ORIGIN 与公钥路径由运营者提供实际值：
npm run publication:sync --workspace @skillflux/web -- --registry REGISTRY_ORIGIN --trust-key PUBLIC_KEY_JSON
npm run publication:build --workspace @skillflux/web -- --registry REGISTRY_ORIGIN --trust-key PUBLIC_KEY_JSON
npm run publication:watch --workspace @skillflux/web -- --registry REGISTRY_ORIGIN --trust-key PUBLIC_KEY_JSON --interval 60
```

命令中的大写参数名是待提供的实际运行配置，不是已存在的域名、密钥或对外发布状态。

### 4.5 安全、隐私与咨询留存

- 网络边界校验协议、地址、Origin、请求大小和限流；敏感请求不能被重定向到其他服务器。
- 本地与云端文件操作防路径穿越、符号链接替换、特殊文件名和保留元数据路径覆盖。
- 签名校验、内容哈希、不可变版本、计划绑定与项目锁共同保护安装；加载前检测本地篡改。
- HTML 和内嵌 JSON 正确转义，原始文本不能变成可执行脚本；私钥、token 和私人评测不进公开产物。
- 长时间运行的 MCP 应重新读取项目权限与广告关闭策略，不继续使用已经被用户撤销的缓存授权。
- 商务咨询收集姓名/联系信息、公司、产品、网址、需求与用途同意；同一请求安全重试不得重复创建线索。
- 咨询状态为新建、跟进、完成、无效；完成或无效满 180 天清理个人信息，保留必要状态审计。未关闭的跟进线索不冒充已经到期。
- 用户“不登录”不等于商务表单“不收集联系方式”；必须清楚解释数据用途。
- 备份中的个人信息和密钥也需要独立的访问控制与留存管理。

### 4.6 备份、恢复与部署

- 网站与 Registry 分开构建和运行；生产 API 使用明确配置的安全地址与持久数据卷。
- SQLite 单实例服务可作为当前架构；不宣称多个网络卷写入实例或进程内限流具备分布式反作弊能力。
- 备份必须包含数据库一致快照和匹配密钥，不能只复制数据库主文件而遗漏 WAL 中的数据。
- 备份附签名清单和文件哈希；检查密钥匹配、数据库完整性、外键与关键账本约束。
- 恢复只允许写入新的目标目录，不能覆盖运行中的数据；恢复后验证旧公钥、原包、资格证明和账本仍然有效。
- 私钥备份属于敏感材料，不上传公开对象存储或随网页发布。
- 正式 npm 发布、域名部署、第一批真实精品评测、真实广告合同和素材都必须有实际配置与证据；不能用文档或测试样本代替。

## 5. 风险、执行顺序与验收（Risks & Roadmap）

### 5.1 主要风险与处置

| 风险 | 处置要求 |
| --- | --- |
| 第三方 AI 不输出广告 | 明确 MCP 无法强制；结构化提供广告，受控 CLI 单独保证输出流程 |
| 页面可抓取但未被收录 | 正确提供静态内容与索引，持续观察真实结果，不承诺训练、收录或排名 |
| 把扫描当成人测 | 分开保存自动与人工证据，后端门禁绑定内容，模拟记录不满足生产发布 |
| 历史版本无法补测 | 用外置签名资格证明恢复原版本，保持原包不可变 |
| 用户项目被自动升级或覆盖 | 只读检查、精确目标、明确授权、固定策略、编辑保护与事务恢复 |
| 广告并发超额或重复计费 | 事务化预留、去重、跨进程测试、暂停永久失效与到期清理 |
| 统计看似有量但没有展示 | 严格区分决策、客户端确认、点击、CTR、花费与回款 |
| 静态内容与云端状态不同步 | 签名同步、原子重建、快照时间、撤销发布与 Runtime 实时门禁 |
| 测试样本被当成真实精品 | 隔离临时数据、明确标注、默认生产快照不灌入合成审批 |
| 部署密钥或私人评测泄露 | 数据目录隔离、内存 token、公开字段白名单、打包/构建扫描和备份权限 |
| 严格宿主拒绝含点号的 MCP 工具名 | 在四种目标宿主实测 `skillflux.*` 命名；如被拒绝改为 `skillflux_*` 下划线命名并同步文档与客户端 |

### 5.2 执行顺序

下列顺序用于控制依赖，不代表只交付某个缩减阶段：

1. 固定产品边界与公开/私密数据模型。
2. 完成 Registry 质检、版本、依赖、撤销、补测和签名基础。
3. 完成 npm、显式入口、本地 MCP、授权安装、更新维护和安全恢复。
4. 完成静态黄页、场景内容、精品版本页、机器索引和签名发布流水线。
5. 完成广告投放、预算计量、咨询、举报、报表与内部运营台。
6. 进行真实 HTTP、真实 MCP、干净 npm 安装、禁用 JS、移动端、异常与攻击式验收，修复发现的问题。
7. 核对正式配置、真实人工评测和商业素材，再执行经授权的对外发布与运营。

不能把“功能已编码”“单元测试通过”“测试数据审批成功”和“真实业务已经上线”混为一谈。
